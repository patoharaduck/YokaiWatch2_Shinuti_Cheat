# Yokai Watch 2 Tools (CTRPluginFramework プラグイン) - ビルド手順

妖怪ウォッチ2(元祖/本家/真打)向けのCTRPluginFrameworkプラグインです。

対応タイトルID(`CTRPluginFramework.plgInfo` の `Targets` に設定済み):

| バージョン | Low TitleID | 完全なTitleID |
|---|---|---|
| 元祖 | 0x0012F900 | 000400000012F900 |
| 本家 | 0x0012F800 | 000400000012F800 |
| 真打 | 0x00155100 | 0004000000155100 |

## 必要なもの

- Docker Desktop (インストール済み)
- devkitPro / devkitARM (インストール済み、`DEVKITARM`/`DEVKITPRO`環境変数設定済み)
- v2対応の`3gxtool`(`ThePixellizerOSS/3gxtool`をビルドし`/opt/devkitpro/tools/bin/3gxtool`に配置済み)
- Luma3DS v13.4 (公式LumaTeam版、プラグインローダー内蔵)

## ビルド手順

**重要:** ローカルのdevkitARMで直接`make`すると、libctrpf 0.8.0(古いツールチェーンでビルド済み)とのC++ ABIの不一致により、
メニューを開いた際に`Fatal plugin error / abort()`でクラッシュします。
**必ずDockerコンテナ経由でビルドしてください。**

```bash
cd ~/Downloads/BlankTemplate

# 前回のビルド成果物を削除
rm -f workspace.elf workspace.3gx BlankTemplate.elf BlankTemplate.3gx

# libctrpf 0.8.0と同じツールチェーンのDockerコンテナ内でビルド
docker run --rm -v "$PWD":/workspace -w /workspace pablomk7/libctrpf:0.8.0 make

# 出力ファイル名をリネーム(コンテナ内では /workspace 固定のため workspace.elf/.3gx になる)
mv workspace.elf BlankTemplate.elf
mv workspace.3gx BlankTemplate.3gx

# フォーマットを確認 (3GX$0002 であることを確認)
xxd -l 8 BlankTemplate.3gx
```

コンテナ内蔵の3gxtoolが古い場合、`3GX$0001`(古い形式)になることがあります。
その場合は、コンテナで作られた`.elf`(ABIは正しい)を、手元のv2対応3gxtoolで再パッケージしてください。

```bash
3gxtool -s BlankTemplate.elf CTRPluginFramework.plgInfo BlankTemplate.3gx
xxd -l 8 BlankTemplate.3gx   # 3GX$0002 になっていればOK
```

## 実機への導入手順

1. SDカードの `/luma/plugins/` 以下に、対象タイトルIDのフォルダを作成し `.3gx` を配置:
   - 元祖: `/luma/plugins/0012F900/`
   - 本家: `/luma/plugins/0012F800/`
   - 真打: `/luma/plugins/00155100/`
2. 対象の妖怪ウォッチ2を起動 → SELECTボタンでプラグインメニューを呼び出す

## 実装済みの機能 (v0.7.0)

メニュー構成 (SELECT で開く):

- **お金**
  - お金を設定する (入力) … キーボードで 0〜999999 を入力
  - お金を 999999 にする
- **アイテム**
  - 所持アイテムを全て 99 個にする (所持数 1 以上のスロットのみ)
- **妖怪 (先頭254体)** … 空きスロットは自動スキップ
  - HP を 999 にする
  - 全ステータスを 999 にする / ちから / ようりょく / まもり / すばやさ を個別に 999
  - 技レベルを全て最大にする
- **バトル時の敵変更** … 次のバトルの相手を 8 体から選択
- **真打専用** (`Sources/cheats_wiki.cpp`、出典: wikiwiki.jp/3ds_codes 妖怪ウォッチ2 真打。真打以外では実行を拒否)
  - 妖怪データ (全スロット): 全妖怪レベル変更 / 全ステータス変更 (〜9999) / 個体値プリセット /
    ニックネーム「ぬね」の妖怪だけ ID・レベル・ステータス・個体値(プリセット/手入力)・技レベルを変更
  - 妖怪スキル変更: 10 体 × 16 スキルを一覧から選択、全員元に戻す (セーブ前に必ず戻す)
  - ワープ: 45 マップから選択 or マップID直接入力、現在マップID表示 (A+B を押しながらマップ移動で反映)
  - 主人公・お供: 性別 (ケータ/フミカ)、お供・主人公モデルを顔アイコン選択 or ID 入力で変更
  - ゲーム動作の変更 (チェックボックス): 友達チャンス確定 / ボス保存 / 大辞典全妖怪表示 / アイテム未所持でも限定妖怪出現 /
    お金が減らない / 「ぬね」の妖怪のHPが減らない。チェックを外すと毎フレームの監視 (`CheatsFrameCallback`) が元の命令に戻す
  - その他: ジバニャンS・コマさんS 出現、元祖/本家限定クエスト受注可能、ガシャ残り回数 255、1日制限解除
    (メモ由来の 0x031xxxxx 系アドレスは +0x055FF000 で 0x087xxxxx に変換: 消費アイテム 03124668→08723668 で整合を確認)
  - 座標ツール: 主人公の座標アドレスは未判明なので、内蔵 Search で見つけた X(float) アドレスを登録して使う。
    現在座標表示 / 直接入力 / 位置の記憶 3 スロットと移動 / XYZ ±10
  - 妖怪・アイテム 一覧から変更 (`Sources/cheats_ids.cpp`): 「ぬね」の妖怪を約400体の一覧から選んで変更、
    もちもの画面でカーソル中のアイテムの個数変更 / 別アイテムへの変換 (コイン・道具・魂・だいじなもの約200種)
    妖怪一覧にはボス妖怪 (No.388〜448) と敵専用・図鑑外 (約200 ID) も収録
  - 妖怪エディタ 画面版 (`Sources/cheats_ui.cpp`): 「エディタ画面を開く」にチェック→メニューを閉じると下画面にタッチ式フォーム
    (3ページ: 基本/技/個体値・保存)、上画面に要約を常時表示。OSD::Run で描画、GameFunc で Touch を処理
  - 妖怪エディタ メニュー版 (`Sources/cheats_more.cpp`): 手持ち/預かりの妖怪をスロット一覧 (名前+Lv 表示) から選び、
    種族 (一覧/ID) ・レベル・HP/ちから/ようりょく/まもり/すばやさ・個体値・技レベル・物理技ID・元祖/本家・決めポーズ・肉体改造値を編集
  - 移動系 (チェックボックス): A+十字キー / A+スティック で座標移動、B ムーンジャンプ、B 上昇、A/X ジャンプ、ウィスパー移動、
    スピードハック 1/2、スタミナ無限、階段でも自転車、自転車で室内、各種アクション (座標は 0x08852E10/14/18、Rzera 氏コードより)
  - バトル系 (チェックボックス): ダメージ最大 65535、必殺技無限、クリティカル確定、攻撃全回避、ボス保存(別版)
  - 装備・魂: そまつなうでわ +127、装備2枠、装備判定削除、所持魂レベル10、神けいけんちだま1個でLv99
  - その他2: JP/GP MAX、レジェンド再開放、ガシャ99、全妖怪 元祖/本家 化、全妖怪物理技変更、決めポーズ全開放、無限売却、チャット加速、FPS60、1日1回イベント無限
  - 入れていないもの: オンライン対戦の番付・勝ち点・KP を書き換えるコード (他プレイヤーに影響するため)
  - 注意: 元祖/本家のアドレスは資料によって食い違う (JourneyOver: 元祖=真打と同じ, 本家=+0x2000 / 別資料: 元祖本家=+0xE000)
    ため、真打以外は「お金」以外未対応のまま
  - 未実装: ASM 注入タイプ (妖怪全部入手・アイテム全部入手・妖怪作成・アイテム作成・DL限定妖怪戦闘) は
    `Assets/ARコード_真打_ASM系(未移植).txt` にまとめてあるので、プラグイン内蔵の Action Replay メニューに貼って試す

### アドレスの出典と検証状況

| 項目 | 元祖/真打 (基準) | 本家 | 検証 |
|---|---|---|---|
| お金 | 0x08722BF8 | +0x2000 | 真打で実機確認済み |
| アイテム所持数 | 0x08723668 + n*0x10 の +4 (8bit, 真打) / 第2表 0x087251D4 + n*0x14 | - | 未検証 (真打専用に変更) |
| 妖怪データ | 0x0870DBDE 〜 (1体 0xC4 バイト) | +0x2000 | 未検証 |
| 敵変更 | 0x08722CF0 | +0x2000 | 未検証 |

- 出典: JourneyOver/CTRPF-AR-CHEAT-CODES (元祖 000400000012F900.txt / 本家 000400000012F800.txt)、敵変更はユーザー提供の AR コード
- 元祖と本家は全アドレスが +0x2000 ずれているだけなので `VersionAddress()` で吸収している
- 真打はお金のアドレスが元祖と一致したため、他も同配置と推定して実装。**初めて使う前にセーブのバックアップを取ること**

### コードの構成

- `Sources/main.cpp` … メニュー登録 (`InitMenu`)、お金入力、敵変更
- `Sources/cheats.cpp` / `Includes/cheats.hpp` … アイテム・妖怪系チート、バージョン差分ヘルパー
- 新しいチートは `cheats.cpp` に関数を追加し、`cheats.hpp` に宣言、`main.cpp` の `InitMenu()` で `menu += ...` する

### オンラインプレイについて

- 3DS の公式オンライン (ニンテンドーネットワーク) は 2024 年 4 月に終了済み。現在オンライン対戦/交換を行うには Pretendo などの非公式サーバー環境が別途必要で、これはプラグインとは無関係の設定
- このプラグインはオフラインでの利用を前提にしている。改造した妖怪やアイテムを使って他のプレイヤーと対戦・交換することは相手に迷惑をかける行為なので行わないこと

## 既知の問題

- ゲーム終了時 (ソフト終了・電源長押しどちらでも) に、CTRPluginFramework自体の
  終了処理まわりの不具合により「An exception occurred (data abort in _free_r)」画面が表示されることがあります。
  - `InitMenu()`を完全に空にしても発生するため、プラグイン側のコードの問題ではなく、
    libctrpf 0.8.0のメニューシステム自体に起因すると考えられます。
  - v0.2.0 で `delete menu;` を外して様子を見ている (改善したかは要確認)。
  - `UsePrivateMemory: true` は起動時クラッシュになるため使えない (5MiB/16MiB とも)。
  - セーブデータや動作への実害は確認されていません。

## 次のステップ: チートを追加する

- `Sources/main.cpp` の `InitMenu()` に `menu += new MenuEntry(...)` の形で項目を追加していきます
- メモリ書き込みには `Process::Write32(address, value)` / `Process::Read32(address, value)` を使用
- 数値入力には `Keyboard` クラスを使用(`Keyboard::Open(std::string &output, const std::string &start)`)
- 改変したいメモリアドレスは、プラグイン自体のメモリサーチャー機能や、外部のARコードデータベース
  (JourneyOver/CTRPF-AR-CHEAT-CODES 等)を参考にします
